# Janet

My personal interactive landing page. Live at [thiago.page](https://thiago.page).

Originally built in 2019 on top of react-boilerplate (webpack 4, Redux, redux-saga, MUI v4, react-intl); fully rewritten in 2026.

## Stack

- [React](https://react.dev) 19 + TypeScript (strict)
- [Vite](https://vite.dev)
- [react-router](https://reactrouter.com) v7
- [motion](https://motion.dev) for animations
- CSS Modules + [@fontsource](https://fontsource.org) self-hosted fonts
- Vitest + Testing Library
- Firebase Hosting

## Getting started

```sh
nvm use   # Node 24
npm install
npm run dev
```

| Command           | What it does                          |
| ----------------- | ------------------------------------- |
| `npm run dev`     | Start the dev server                  |
| `npm run build`   | Typecheck + production build to `dist` |
| `npm run test`    | Run the test suite (Vitest)           |
| `npm run lint`    | ESLint (flat config)                  |
| `npm run typecheck` | TypeScript check only              |
| `npm run preview` | Serve the production build locally    |

## Deploying

```sh
npm run deploy
```

Builds and deploys to Firebase Hosting (project: `landing-17ce5`).

### The service worker kill-switch

The 2019 build shipped a service worker (`sw.js`, generated by `offline-plugin`) that precached everything. `public/sw.js` is a no-op that unregisters itself, so returning visitors are freed from the old cache. Once traffic from the old build has aged out (a few months), it can be deleted along with the `Cache-Control: no-cache` header for it in `firebase.json`.
